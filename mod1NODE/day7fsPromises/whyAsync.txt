# Ab Async Version

```js

```

```txt

```

and

```txt
libuv ko kaam deta hai
```

---

Worker file padh leta hai.

Phir:

```txt
resolve(data)
```

kar deta hai.

---

Agar:

```js

```

hai.

To async function pause rehti hai.

Pure Node nahi.

Sirf us function ka remaining part.

---

# Biggest Misconception

People think:

```js
await fs.readFile(...)
```

means

```txt
Node wait kar raha hai
```

Wrong.

Actually:

```txt
File worker thread padh raha hai.
```

Node dusre requests handle kar raha hota hai.

---

# Real Backend Example

100 users.

Sab request bhejte:

```js
fs.readFile(...)
```

Node:

```txt
User1 -> worker
User2 -> worker
User3 -> worker
User4 -> worker
```

Background me kaam.

Main JS thread mostly free.

Isi wajah se Node scalable lagta hai.

# Ab ek question

Code:

```js
console.log("1");

fs.readFile("a.txt", () => {
  console.log("2");
});

console.log("3");

setTimeout(() => {
  console.log("4");
}, 0);

console.log("5");
```

Without guessing:

1. Pehle synchronous lines kaunsi chalengi?
2. File padhne ka kaam kaun karega?
3. Callback ko queue me kaun dalega?
4. `"2"` aur `"4"` me kaun pehle aane ke chances zyada hain, aur kyun? (exact guarantee nahi, reasoning chahiye)
